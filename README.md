## 📌 О проекте

**GP Verify Bot** помогает сделать общение в чатах жилого комплекса более доверительным.

Бот проверяет, состоит ли автор сообщения хотя бы в одной подключенной закрытой группе дома. Если пользователь найден, бот ставит на его сообщение реакцию **👌** в выбранном целевом чате.

```text
Пользователь написал сообщение в целевом чате
        ↓
Бот берет Telegram user_id автора
        ↓
Проверяет наличие пользователя в закрытых группах домов
        ↓
Если пользователь найден хотя бы в одной ЗГ
        ↓
Бот ставит реакцию 👌
```

Для пересланных сообщений бот проверяет **того, кто переслал сообщение в целевой чат**, а не автора оригинального сообщения.

## 🧩 Термины

| Термин | Описание |
|---|---|
| **ЗГ** | Закрытая группа дома, источник проверки членства |
| **Целевой чат** | Чат, где бот ставит реакцию 👌 |
| **Подтвержденный пользователь** | Пользователь, найденный хотя бы в одной подключенной ЗГ |
| **Владелец** | Главный администратор бота, заданный через `OWNER_ID` |

## ✨ Возможности

- Проверка автора сообщения по нескольким закрытым группам домов.
- Поддержка нескольких целевых чатов.
- Единая реакция для подтвержденных участников – 👌.
- Кеширование результатов проверки.
- Управление только для владельца и назначенных администраторов.
- Админ-меню через Telegram.
- Журнал действий администраторов.
- Технический лог обработки сообщений.
- Работа без публичного IP через long polling.

---

## 🔒 Принципы приватности

Бот **не хранит**:

- тексты сообщений;
- историю переписки;
- список участников закрытых групп;
- информацию о том, в какой именно закрытой группе найден пользователь;
- телефоны и другие лишние персональные данные.

В базе хранится только служебная информация, необходимая для работы.

## ⚙️ Переменные окружения

Создайте файл `.env` на основе `.env.example`.

```env
BOT_TOKEN=your_bot_token_here
OWNER_ID=123456789
DB_PATH=/data/bot.sqlite3
CACHE_TTL_MINUTES=30
DEFAULT_REACTION=👌
```

| Параметр | Описание |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота от BotFather |
| `OWNER_ID` | Telegram user_id владельца бота |
| `DB_PATH` | Путь к SQLite-базе |
| `CACHE_TTL_MINUTES` | Время жизни кеша проверки пользователя |
| `DEFAULT_REACTION` | Реакция для подтвержденных участников |

## 🚀 Локальный запуск

Создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте окружение в Windows:

```bash
.venv\Scripts\activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

Создайте `.env`:

```bash
copy .env.example .env
```

Заполните `BOT_TOKEN` и `OWNER_ID`.

Запустите бота:

```bash
python -m app.main
```

## 🐳 Запуск в Docker

Сборка и запуск:

```bash
docker compose up -d --build
```

Просмотр логов:

```bash
docker compose logs -f
```

Остановка:

```bash
docker compose down
```

Контейнер не требует открытых входящих портов, так как бот работает через **long polling** и сам обращается к Telegram API.

## 🤖 Права бота в Telegram

### В закрытых группах домов

Бот должен быть добавлен в каждую ЗГ, которую нужно использовать как источник проверки.

Рекомендуется назначить бота администратором в каждой ЗГ, чтобы он мог надежно проверять членство пользователей.

### В целевых чатах

Бот должен быть добавлен в каждый чат, где нужно ставить реакцию 👌.

Рекомендуется назначить бота администратором в целевых чатах, чтобы он стабильно видел сообщения и мог выполнять необходимые действия.

Также в настройках целевого чата должна быть разрешена реакция 👌.

## 🛡️ Безопасность управления

Управлять ботом могут только:

- владелец, указанный в `OWNER_ID`;
- администраторы, добавленные владельцем.

Проверка прав выполняется по Telegram `user_id`, а не по username.

```text
username можно изменить
user_id остается постоянным
```

Все административные действия записываются в журнал аудита.

## 👌 Логика проверки

Пользователь считается подтвержденным, если его статус хотя бы в одной подключенной ЗГ:

```text
creator
administrator
member
```

Пользователь считается неподтвержденным, если бот не нашел его ни в одной подключенной ЗГ.

Кеш хранит только общий результат:

```text
user_id → подтвержден / не подтвержден
```

Бот не хранит, в какой именно ЗГ найден пользователь.
