## 📌 О проекте

**GP Verify Bot** помогает сделать общение в чатах жилого комплекса более доверительным.

Бот проверяет, состоит ли автор сообщения хотя бы в одной подключенной закрытой группе дома. Если пользователь найден хотя бы в одной ЗГ, бот ставит на его сообщение реакцию **👌** в выбранном целевом чате.

```text
Пользователь написал сообщение в целевом чате
        ↓
Бот берет Telegram user_id автора
        ↓
Проверяет наличие пользователя в подключенных ЗГ домов
        ↓
Если пользователь найден хотя бы в одной ЗГ
        ↓
Бот ставит реакцию 👌
```

Для пересланных сообщений бот проверяет **того, кто переслал сообщение в целевой чат**, а не автора оригинального сообщения.

## 🧩 Термины

| Термин | Описание |
|---|---|
| **ЗГ** | Закрытая группа дома, источник проверки членства |
| **Целевой чат** | Чат, где бот ставит реакцию 👌 |
| **Подтвержденный пользователь** | Пользователь, найденный хотя бы в одной подключенной ЗГ |
| **Владелец** | Главный администратор бота, заданный через `OWNER_ID` |
| **Администратор бота** | Пользователь, которому владелец разрешил управление ботом |
| **Мягкий режим** | Администратор выполняет действие сразу, владелец получает уведомление |
| **Строгий режим** | Действие администратора требует подтверждения владельца |

## 🔒 Принципы приватности

Бот **не хранит**:

- тексты сообщений;
- историю переписки;
- список участников закрытых групп;
- информацию о том, в какой именно закрытой группе найден пользователь;
- телефоны и другие лишние персональные данные.

В базе хранится только служебная информация, необходимая для работы:

```text
user_id
chat_id
название подключенного чата
общий результат проверки: подтвержден / не подтвержден
служебные события и действия администраторов
```

## ⚙️ Переменные окружения

Создайте файл `.env` на основе `.env.example`.

```env
BOT_TOKEN=your_bot_token_here
OWNER_ID=123456789
DB_PATH=/data/bot.sqlite3
CACHE_TTL_MINUTES=30
DEFAULT_REACTION=👌

# soft   - админ выполняет действие сразу, owner получает уведомление
# strict - действия админа требуют подтверждения owner
ADMIN_APPROVAL_MODE=soft
```

| Параметр | Описание |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота от BotFather |
| `OWNER_ID` | Telegram user_id владельца бота |
| `DB_PATH` | Путь к SQLite-базе внутри контейнера |
| `CACHE_TTL_MINUTES` | Время жизни кеша проверки пользователя |
| `DEFAULT_REACTION` | Реакция для подтвержденных участников |
| `ADMIN_APPROVAL_MODE` | Режим управления: `soft` или `strict` |

## 🤖 Права бота в Telegram

### В закрытых группах домов

Бот должен быть добавлен в каждую ЗГ, которую нужно использовать как источник проверки.

Рекомендуется назначить бота администратором в каждой ЗГ, чтобы он мог надежно проверять членство пользователей через `getChatMember`.

### В целевых чатах

Бот должен быть добавлен в каждый чат, где нужно ставить реакцию 👌.

Рекомендуется назначить бота администратором в целевых чатах, чтобы он стабильно видел сообщения и мог выполнять необходимые действия.

Также в настройках целевого чата должна быть разрешена реакция 👌.

## 📋 Команды

### Общие команды

```text
/start
/menu
/register_source Название
/register_target Название
/sources
/targets
```

| Команда | Где выполнять | Описание |
|---|---|---|
| `/start` | Личный чат с ботом | Открыть меню |
| `/menu` | Личный чат с ботом | Открыть меню |
| `/register_source Название` | В закрытой группе дома | Добавить текущий чат как ЗГ |
| `/register_target Название` | В целевом чате | Добавить текущий чат как целевой |
| `/sources` | Личный чат с ботом | Показать список ЗГ |
| `/targets` | Личный чат с ботом | Показать список целевых чатов |

### Команды владельца

```text
/mode
/mode_soft
/mode_strict
/remove_source_ID
/remove_target_ID
```

| Команда | Описание |
|---|---|
| `/mode` | Показать текущий режим управления |
| `/mode_soft` | Включить мягкий режим |
| `/mode_strict` | Включить строгий режим |
| `/remove_source_ID` | Исключить ЗГ из обработки |
| `/remove_target_ID` | Исключить целевой чат из обработки |

Пример исключения чата:

```text
/remove_source_3
/remove_target_5
```

ID берется из списков `/sources` и `/targets`.

## 🔐 Режимы управления

### soft

Мягкий режим.

Администратор может сразу добавить ЗГ или целевой чат в обработку. Владелец получает уведомление о действии.

### strict

Строгий режим.

Действие администратора не применяется сразу. Бот создает заявку и отправляет владельцу кнопки подтверждения или отклонения.

Владелец может:

```text
✅ Одобрить заявку
❌ Отклонить заявку
```

---

## 👌 Логика проверки

Пользователь считается подтвержденным, если его статус хотя бы в одной подключенной ЗГ:

```text
creator
administrator
member
```

Пользователь считается неподтвержденным, если бот не нашел его ни в одной подключенной ЗГ.

Кеш хранит только общий результат:

```text
user_id → подтвержден / не подтвержден
```

Бот не хранит, в какой именно ЗГ найден пользователь.

## 🛡️ Безопасность управления

Управлять ботом могут только:

- владелец, указанный в `OWNER_ID`;
- администраторы, добавленные владельцем.

Проверка прав выполняется по Telegram `user_id`, а не по username.

```text
username можно изменить
user_id остается постоянным
```

Все административные действия записываются в журнал аудита.
